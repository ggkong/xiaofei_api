# 关键词规则

管理员从侧栏“关键词规则”进入 `/admin/keyword-rules`。功能拥有独立总开关，每条规则也可单独暂停。编辑、导入和开关修改均在“保存并生效”后应用；关闭功能保留规则。原有关键词配置在首次保存时迁入，之后统一在此管理，语义风控的其他配置继续独立生效。

## 批量添加与导入

- TXT：每行一个关键词，追加到当前规则。
- CSV：选择“导入多条独立规则”，每行可配置不同回复或注入内容。逗号、双引号、多行内容遵循标准 CSV 引号规则。
- JSON：导入本页导出的完整规则，保留排除词、优先级和适用范围。导入默认追加，也可明确选择替换；不会自动打开总开关。

```csv
名称,关键词,动作,回复,注入,匹配方式,分类
使用帮助,查询使用说明,回复,请查看团队帮助中心,,完全一致,客服
编程指导,代码示例,注入,,回答时优先提供可运行的代码与验证步骤,包含,开发
```

最多 500 条规则、每条 5,000 个关键词，总计 50,000 个关键词；单词最多 512 个字符。导入文件与完整规则配置最多 4 MiB。正则表达式总计最多 100 条，使用 Go RE2 语法。

## 匹配和动作

默认“完全一致、区分大小写、只扫描本次用户提问”。比较时去掉提问与普通关键词两端空白，保留内部空格、标点和大小写，不做同义词或模糊匹配。可选择包含、整词、开头、结尾、正则表达式；正则保留原始空白。整词边界按 Unicode 字母、数字和下划线判断，不做中文分词。多关键词可选择任意命中或全部命中。

排除词按原文包含判断，遵循规则的大小写选项。支持限定用户、分组、公开模型标识和协议，或排除指定用户、模型。扫描历史消息需明确选择“全部用户消息”或“完整上下文”；不扫描图片、音频等媒体数据。

优先级数字越小越先执行，同优先级按列表顺序。自动回复、拦截结束规则处理；自动回复不请求上游、不产生模型用量。提示词注入按规则顺序加入请求的系统指令区，保留原始用户提问，支持放在现有系统指令前或后；也可命中后停止后续规则。后续自动回复或拦截会结束请求，此时先前匹配的注入不会发给模型。

支持 Chat Completions、Responses（含 WebSocket 连续轮次）、Anthropic Messages 和 Gemini。对话记录展示命中规则及实际保存的注入后上下文；未向模型发起请求的自动回复不会伪造上游模型信息。

## 搜索与预览

支持按名称、关键词、回复、注入内容搜索，结合分类、动作、匹配方式、启用状态筛选。“命中预览”使用当前草稿模拟，无需开启总开关，也不会调用模型或改变保存的规则。默认跳过暂停的规则，可选择包含暂停规则。可指定模型、用户、分组与协议并检查注入后的完整请求。

## 管理接口

仅管理员浏览器 JWT 可用，成员、管理员 API Key 和受限管理凭证均不可访问，响应使用 `Cache-Control: no-store`：

- `GET /api/v1/admin/keyword-rules`：读取规则及 `revision`。
- `PUT /api/v1/admin/keyword-rules`：提交完整配置和读取到的 `revision`；并发编辑冲突返回 409，不覆盖本地草稿。
- `POST /api/v1/admin/keyword-rules/test`：提交 `policy`、`text`、`protocol` 和可选 `model/user_id/group_id`，返回命中、动作和有效请求。也可传 `request` 模拟完整上下文。

配置保存在现有 settings 表的 `keyword_rules_config`，不引入数据库迁移。保存立即更新当前进程缓存；外部设置变化最多约一秒刷新。HTTP 及 WebSocket 均先完成已有模型准入检查。原有输入审计检查原始提问，系统注入内容不会被误认成用户输入。

## AI 辅助生成

从“AI 辅助生成”选择自己的可用 API Key 与文本模型，描述希望识别的问题，可填写固定回复或注入提示词。生成新的独立规则，或为当前规则补充明确的新触发词；默认仍采用精确、区分大小写匹配。生成模型和实际适用模型范围分别设置。

AI 给出候选词、用法解释、命中与不命中示例。示例由现有匹配引擎实际核对；未通过核对的建议不可加入。选中的新规则仅加入草稿且默认暂停，需检查、启用并保存。扩充现有规则保持其回复、匹配方式、范围和开关，保存后应用新增关键词。全局开关不会被 AI 改动。用法说明会随规则保存，支持编辑及 JSON 导入导出。

生成使用标准 `/v1/chat/completions` 路径，遵循所选 Key 的鉴权、IP/模型限制、额度、用量计费、输入审计和对话留存。不会创建隐含密钥或绕过现有关键词策略。只有需求和选中的当前规则发送给模型，不自动读取成员历史聊天。生成最多 5 条规则，每条最多 15 个候选词，120 秒超时；请求取消、修改需求或关闭弹窗后不会接受迟到结果。模型输出经过字段与长度校验，不能指定权限范围或自动启用规则。命中核对调用原有 `/admin/keyword-rules/test`，不会额外调用模型。
