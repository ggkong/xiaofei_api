# 管理员对话留存、合并展示与关键词回复

管理员页面：`/admin/conversation-archives`。基于 v0.2.19，在
`feature/admin-conversation-archive` 分支开发。生产配置与数据库备份独立保存；
凭据、环境文件、数据库和备份不进入源码仓库。

## 展示与分组

列表展示姓名、模型、最近一次提问与回复，手机端使用卡片，支持正文、姓名、邮箱、
请求模型与转发模型搜索。默认合并展示，也可切换为全部调用。

- 有会话标识：按成员、API Key、会话标识归组，保留不同提问及不同模型。
- 无会话标识：同一成员及 API Key 在服务器当天的完全相同提问归组。
  分组使用完整提问的摘要，不使用截短的列表预览，不做模糊语义合并。
- 没有可用提问的旧记录标为无正文调用；缺失成员归属时保持请求独立。
- 过滤器先选中匹配的组，组内次数、模型及调用选择器覆盖该组全部留存调用。
  按组最新调用游标分页，避免同一组跨页重复。

展开后逐次选择调用，查看本次问答、完整已保存上下文及模型信息。
每次输入是一个上下文快照，不把不同调用的历史简单拼接。工具和系统消息可折叠，
长会话分批展示。内容以安全文本插值呈现，不执行用户或模型生成的 HTML。

分别记录请求别名、实际转发模型、服务商声明模型和客户端可见模型；旧记录缺少的
信息显示“未记录”，不把别名猜成实际模型。成员姓名与邮箱在采集时保存快照。

## 永久留存与重复内容存储

```dotenv
SUB2API_ARCHIVE_IMAGE=sub2api-team:0.2.19-archive.7
CONVERSATION_ARCHIVE_ENABLED=true
CONVERSATION_ARCHIVE_RETENTION_DAYS=0
CONVERSATION_ARCHIVE_MAX_BYTES=4194304
CONVERSATION_ARCHIVE_DEDUP_ENABLED=true
```

采集默认关闭；启用后的默认期限为永久，`0` 不按天自动删除。页面“留存设置”
可将现有记录一并改为永久，及选择每次输入、输出分别 4/8/16 MiB 的上限。
数据库策略优先于环境默认值。已被旧版本删除或省略的内容无法恢复。

迁移 250 为每条调用保留独立记录，并把重复的大块上下文按消息规范化、校验摘要、
压缩后复用。管理员读取详情时完整还原 JSON，保留大整数和工具结构。列表仅返回
摘要，搜索仍可匹配被复用的完整历史。存储版本使用独立数据库列，客户端自带的
同名 JSON 字段不被解释为存储引用。

历史优化使用小批事务：`/app/archive-maintenance compact`。永久期限更新、
写入、优化和无引用块清理使用数据库锁协调，避免丢失共享内容。存储低于 512 MiB
时暂停新的留存写入，保留已有数据；通过留存设置查看容量并扩容。

超过上下文上限时标记省略，尽量保留最新提问和请求模型；原请求仍完整转发。
SSE 逐块采集，不延迟客户端响应；独立状态观察器持续识别完成、失败或中断。
留存写入有超时，数据库故障不会破坏模型响应。崩溃或写入失败仍可能丢失在途记录，
不提供持久化重试队列。结构化凭据字段脱敏，内嵌媒体省略，不采集认证请求头。

## 精确关键词与自动回复

“关键词规则”提供总开关、匹配方式和独立自动回复开关：

- 完整提问完全一致：区分大小写、标点和内部空格，仅忽略首尾空白，默认最严格。
- 包含指定原文：区分大小写的原文子串，不进行同义词或近似匹配。
- 旧规则的忽略大小写包含模式仍能用于拦截，但不能用于自动回复。

只匹配本次最后一条用户提问，跳过历史、系统与工具消息。精确关键词每条最多
200 个字符，超限直接拒绝，不自动截短。回复最多 4000 字符。
总开关关闭时保留配置并正常转发；自动回复关闭时，命中按拦截返回。
自动回复开启并命中时，直接返回正常协议的指定文本，不调用上游、不产生模型用量、
不封禁用户。支持 Chat、Responses、Anthropic、Gemini 的 JSON/SSE 和 Responses
WebSocket 回复格式。归档标记“自动回复、未调用模型”。未填写规则前不开启自动回复。

简化面板使用现有本地前置风险模块，应用于所有分组和模型，不调用外部审查接口、
不发送邮件、不开启自动封号。保存启用规则时会同步刷新总开关，首个请求即生效。

## 采集范围与权限

捕获经过 API Key 认证的 JSON POST `/chat/completions`、`/responses`、`/messages`
及已有别名。上游内部重试对应一条归档，客户端主动重试对应不同调用。
WebSocket、Gemini 原生协议、媒体生成接口暂不归档；关键词回复协议支持不等于
该协议已经支持归档。上游通过 `previous_response_id` 隐式保管的历史无法自动补全。

所有列表、分组、详情、设置、优化和删除 API 要求管理员网页登录 JWT，沿用管理员
认证、确认、限流和审计；普通成员、管理员 API Key 和受限管理员 Key 无权读取。
返回 `Cache-Control: no-store`。删除仅删除指定调用，后台清理不再被引用的上下文块。

## 验证与运维

- Go 测试覆盖协议回复、精确匹配及开关、采集、状态、模型观察和权限。
- 独立 PostgreSQL `archive_test` 覆盖永久期限、分组分页、成员隔离、全文查询、
  共享块删除与清理、完整内容还原、压缩和展开往返。禁止使用生产 DSN。
- 前端执行对话页面、关键词、上下文解析和 i18n 测试、ESLint、完整类型检查及生产构建。
  小内存机器使用 `pnpm run build:archive` 串行检查和打包。
- 使用隔离环境和临时真实 JWT 验证授权上游 JSON/SSE、精确回复、零用量、近似词放行、
  两个开关、成员 403、管理员读取与删除，验证后移除临时身份。
- 上线前备份，仅替换应用容器，保留 PostgreSQL、Redis 及原数据卷。
- 小批清理命令：`docker compose exec -T sub2api /app/archive-maintenance purge`。
  永久记录不因期限删除，只清理确实无引用的数据块。

## 旧版回退

旧应用无法直接读取压缩格式，不能只切换镜像。先备份，关闭归档采集并用当前镜像
仅重建应用，确认没有新留存写入。使用当前版本执行
`docker compose exec -T sub2api /app/archive-maintenance expand`，核实压缩行计数为零，
再恢复旧应用镜像。展开命令先检查空间，不足时停止；保留当前应用和已有数据。
保持新增表和列，不删除、覆盖或恢复整库。定时清理脚本也需随版本一起回退。

## 发布基线

保留上游版本与许可。发布基线已移除上游内置 OAuth client_secret，仅使用显式配置的
`ANTIGRAVITY_OAUTH_CLIENT_SECRET`、`GEMINI_CLI_OAUTH_CLIENT_SECRET` 或自定义 OAuth
配置；缺失时明确报错，官方 API Key 接入不依赖这些配置。测试凭据为运行时虚构值。
GitHub 功能分支从清理后的发布基线继续提交；只推送明确分支，不批量推送旧上游历史。
本地验证、远端 CI 和生产验证应分别记录，不能互相替代。
